0. Core System Principle
The system is not a single linear trade pipeline.
It is a concurrent execution architecture built around this hierarchy:
GLOBAL ENGINE
    ↓
OPPORTUNITY
    ↓
EXECUTION LANE
    ↓
C1 / C2 EXECUTION EVENTS
The universal logic is:
Opportunity → Execution → State Transition → Reaction → Archive
C1 and C2 are not one transaction split in half.
They are separate atomic executions tied by a shared opportunity context and C1 confirmation state.

2. Correct C1 / C2 Meaning
2.1 C1
C1 is the first full arbitrage execution.
It is not just discovery.
It is not only a buy leg.
It is not a lock.
C1 does:
detect executable spread
→ select flashloan size
→ borrow flashloan
→ execute full route
→ verify fills
→ repay flashloan
→ realize profit
→ store C1 state
→ emit confirmation event

the route produced enough output
the flashloan was repaid
profit was realized
C1 creates the reference point for possible C2.

2.2 C2
C2 is a second independent atomic execution.
C2 does not blindly follow C1.
C2 requires:

same opportunity context
block > C1 block

→ repay its own flashloan
→ realize its own profit
→ archive result
C2 proves:
the post-C1 market state still contains executable edge
the second route is profitable by itself
the opportunity can be extended without halting the system

10. Critical Concurrency Rule
C2 lifespan is lane-local.
It must not halt the global system.
Wrong model:
C1 executes
    ↓
entire system waits max 5 blocks
    ↓
C2 executes or expires
    ↓
main engine resumes
Correct model:
C1 executes
    ↓
that C1 opens one C2 lane
    ↓
that lane waits max 5 blocks
    ↓
main engine continues immediately
C2 expiry kills only the lane.
It does not pause:
pool scanning
main C1 discovery
new C1 submissions
other C2 lanes
liquidation scanning

14. Decision Logic
C1 decision
C1 executes only if:
expected_net_profit >= min_profit
fork_sim_success == true
final_balance_after_route >= repayment + minProfit
route_payload_valid == true
gas + relay + risk buffer included
C2 decision
C2 executes only if:
C1 exists
current_block > c1_block
current_block <= c1_block + 5
post-C1 rescan finds executable edge
fresh fork simulation succeeds
expected_net_profit >= min_profit
route payload differs or remains valid intentionally
C2 decision values:
MIRROR      = repeat direction if post-C1 state still favors it
REVERSE     = opposite direction if C1 created reverse imbalance
DO_NOTHING  = no safe executable edge
EXPIRED     = lane exceeded C1 block + 5
FAILED      = attempted but transaction failed or simulation became invalid
